## Findings

### Major

**Q-1 (C1). Texts that start with an amount and carry an inflected currency word, a weekday or a relative day go to the parser and are saved as EUR today.**
Repro: `route(text, date(2026,11,1))` and `parse_entries` on each text, ran in the scratchpad (`mine/c1.py`, `c1b.py`).
Actual: all of these return `parser` and save EUR dated 2026-11-01: `20 фунтов обед` (20.00), `100 злотых обед`, `25 такси в долларах`, `300 гривнах такси` (300 EUR, not UAH), `50 баксах такси`, `25 кофе в долларах` (`25 coffee dollars` and `100 грн такси` are caught); `40 продукты в пятницу`, `25 taxi on friday`, `25 обед в понедельник`, `25 taxi в субботу`, `25 coffee tomorrow`, `25 кофе два дня назад` (date today, not two days ago).
Expected (spec A1.1 and Known risks intent): foreign currency and dates in words go to the AI. The reply shows `EUR` and Undo is one tap, and it matches phase 1.3 behaviour, so it is not a regression; but it is the exact case the AI was meant to remove, and the live run would not show it because `livetest.py` calls `run_turn` directly.
Fix: extend the warning words in `ai_routing.py` with the stems that cover the inflected forms (грн, гривн, долар, доллар, бакс, евро, рубл, злот, фунт, pound, zlot), weekday names in RU, UK, EN, and `назад`, `тому`, `ago`, `tomorrow`, `завтра`, `last`; add tests. The plan fixes the list, so this needs a product-owner ruling.

### Minor

**Q-2 (C2, C5). Failures after the Save commit are not contained.** `await callback.answer()` and `_send_saved` (`entry_budget`, `list_categories`) sit outside any guard in `on_draft_save`.
Repro: draft of 2 entries, `AnswerCallbackQuery` raises `TelegramBadRequest` "query is too old" on Save: `TelegramBadRequest` escapes, 2 entries saved, draft `saved`, 0 replies, draft message keeps its buttons (pressing again says "Already saved."). Same with `entry_budget` raising on the second entry: `OperationalError` escapes, 3 saved, replies after the failure never sent.
Expected: money saved once, replies and the edit still attempted (ledger ruling 7: Telegram failures never undo or skip the rest).
Fix: wrap `callback.answer()` like the other Telegram calls (`TelegramAPIError` logged), and catch `sqlite3.Error` per record in the reply loop.

**Q-3 (C4, C10). Cancel and Save leave the spinner on unexpected errors.** `on_draft_cancel` does not catch `sqlite3.Error` (repro: `cancel_draft` raising `OperationalError` gives `OperationalError` out of the handler, no `answer`). `on_draft_save` catches only `sqlite3.Error` (forced `ValueError` in `save_draft` escapes unanswered). No realistic trigger found for the non-sqlite case.
Expected A6.1 and A6.5: `Could not save...` and every press answered.
Fix: same `except sqlite3.Error` branch in cancel with a reply; for Save catch `Exception` before the commit point.

**Q-4 (C3, C6, C7). Telegram or database failure while sending a draft leaves a misleading state.**
C3 repro: correction with `replaces_open_draft`, first `SendMessage` of the new draft fails with 400: draft 1 `replaced` (message edited to "Replaced by the draft below"), draft 2 `cancelled`, user gets "AI is not available right now. Nothing saved." Nothing saveable is left; he must retype.
C6 repro: `set_draft_message` raises after a successful send: the draft with live buttons is on screen but the reply says "Nothing saved." (the draft is still `open` and Save works).
C7: the `suppress(TelegramAPIError)` around the "[replaced]" edit writes no log line (log check: only the two `ai call` lines).
Fix: send the new draft first, then mark the old one replaced and edit it; log the suppressed edit with the class name; guard `set_draft_message`.

**Q-5 (C9). `livetest` exits 0 when every turn failed and prints nothing until all 15 turns end.** Repro: `run()` with 15 scripted 401 replies returns 35 lines, 15 of them "The AI key is not accepted", and `main()` has no failure exit. For a paid run that is the gate before deploy.
Fix: print each line as it is produced; exit 1 when any turn is a `Failure`.

**Q-6 (C13). SDK retries are not counted by the daily cap.** Repro: real SDK client with `max_retries=2`, two scripted 500s then a text reply: 3 HTTP requests, `ai_calls` counter 1. Worst case 3x the spend per logical call (about $9 a day against the $20 monthly Console limit). Spec A2.7 says "model calls"; ambiguous.
Fix: either accept and note in the spec, or set `max_retries=0` and retry in `_loop` through `_take_call`.

**Q-7 (C14). No size check after download when `file_size` is missing.** Repro: image document with `file_size=None` and 6 MB of data: reaches the model call (1 request). Spec A1.5 says up to 5 MB. Telegram normally sends the size, so rare. Also EXIF GPS in image documents goes to Anthropic as sent (spec A10.3 covers "photos").
Fix: `len(data) > IMAGE_MAX_BYTES` after download gives the same no-reply or `PHOTO_UNREADABLE`.

**Q-8 (C15-C20). Test gaps, behaviour correct today.** My own mutations on a copy: `wanted in r.note` without `casefold` (C16), `>` to `>=` at 48 h in `_open_draft` and `<=` to `<` in `_live_draft_ids` (C17), `>` to `>=` at 2 h in `Memory._expire` (C18), dropping `and turn.source == "text"` in the "earlier draft closed" note (C19), `_media_type` without the `WEBP` check (C20): all survive, 169 tests green. The owner-only guard for photos and `d:` callbacks works (stranger photo: 0 requests, stranger Save press: 0 requests, draft stays `open`, no model call) but has no regression test (C15).
Fix: one test each; a mixed-case-note test, exact 48 h and 2 h tests, a photo draft with a replacing correction, a WAV `RIFF` document, a stranger photo and callback.

**Q-9 (C12). Transitive dependencies unpinned.** 35 packages installed, 2 pinned (`aiogram`, `anthropic`). Same pattern as phase 1 (only aiogram was pinned); the release checklist saves `pip freeze`. Fix: accept, or a constraints file generated from the verified venv.

**Q-10 (C24). `_config/engineering-rules.md` Stack still lists only aiogram.** `anthropic 2.3.0` and `httpx2` (dev) are approved (spec A2.1, plan) but the rules file does not say so. Fix: one line in the file (product owner's file, not the developers').

**Q-11 (C25). Duplication.** `AsyncAnthropic(...)` with the same arguments and the same SDK logger names are built in both `__main__.py` and `livetest.py`; the live check could drift from production. Retry-once is duplicated in `handlers.py` and `ai_handlers.py`. Fix: `livetest` imports the builder from `__main__`; not worth a separate task for the rest.
