## Findings (new, all minor)

- **Q-1 A year typo files the entry in the future.** `25 coffee 15.11.2027` is saved on 2027-11-15. Neither the reply nor /last shows the year, and /month says "No entries." A test pins this behaviour. Expected: an error, or the date shown in the reply.
- **Q-2 Oversized replies and duplicates.** A 4080-character note produces an 8211-character confirmation, over Telegram's 4096 limit. Five 800-character notes make /month 4228 characters, and the daily job would then fail every day. When the reply fails after the entry is committed, retyping saves a second entry. QA did not reproduce the claim that a long pot name breaks /month for good: /undo hides the pot.
- **Q-3 Rate extremes.**
  - After `/rate usd 99999999999999999999999999`, every `25 usd x` raises, gets no reply, and nothing is saved until the next `/rate`.
  - `/rate uah 0.000001` converts a pending 1200 UAH to 0 cents. A later correct rate does not reconvert it.
- **Q-4 Edited messages are ignored.** Editing `250 coffee` to `25 coffee` leaves 250.00 saved, with no reply. The spec is silent on this.
- **Q-5 Old buttons act silently.** Telegram sends an InaccessibleMessage for buttons on messages older than 48 hours. Undo still deletes the entry and a category pick still writes it, but there is no feedback and the message is not updated. This was built by hand, not run against Telegram.
- **Q-6 Callback data is not validated.** `p:1:13` puts "Salary" on an expense. A bad category id raises IntegrityError, and a huge id raises OverflowError. Only a modified client can send this, and access is owner-only.
- **Q-7 Wrong copy.** `/goal 200 5000` answers "Start it with: save 100 200", a command the parser itself rejects.
- **Q-8 Negative percent.** A pot pushed below zero (known item 3) shows "-6%" in /savings and /month.
- **Q-9 CSV formula cells.** Notes starting with `= + - @` are exported raw. Excel or Numbers may read them as formulas. This is relevant to acceptance step 8.
- **Q-10 deploy.sh step 8 (by reading).** `systemctl is-active A B` exits 0 if any one unit is active, so a crash-looping bot passes while the timer is active.
- **Q-11 deploy.sh rollback line (by reading).**
  - The line is printed after any failure from step 3 on, but the database is first touched at step 7. Pasting the line then loses entries made since the step-2 backup.
  - The mode of the server `.env` file is not checked.
- **Q-12 Daily job and entry-point visibility (by reading).**
  - A backup failure also blocks that day's summary (one try block, plan order).
  - `__main__` loads settings outside its try, so a bad `.env` repeats a raw traceback every 5 seconds.
  - OwnerOnly drops foreign updates with no log line.
  - A failed daily job exits 1 with no alert.
- **Q-13 Leap day.** `25 coffee 29.02` typed before 29 February in a leap year (and in the year after) gets the date error. The full date works.
- **Q-14 .gitignore gaps.** `.env.prod`, `.env.local`, `*.key`, `secrets/`, `*.csv` and `*.sqlite*` are not ignored.

**T-1 Test gaps.** Current behaviour is correct, but a regression would pass. QA mutated a scratch copy: 12 of 15 mutations survived with 312 tests passing.
