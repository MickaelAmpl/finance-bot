# Phase 1.4: AI input (implementation plan)

Status: build authorised by Misha on 2026-11-12 together with the spec ("утверждаю"; build straight after the plan, no separate plan approval). Decision row 12.11 in `shared/decisions.md`.

> For agentic workers: the product owner runs this plan with superpowers:subagent-driven-development, one developer per task, a `two-axis-review` after each task, one closing whole-branch review, then stage 05 QA.

**Goal:** Misha writes free text or sends a receipt photo; Claude Sonnet 5.5 drafts entries that are saved only after he presses Save; he can ask about his money and gets numbers the bot computed.

**Architecture:** Text that the phase 1.3 parser handles cleanly stays on the parser; everything else (with the key set) goes through one async tool loop (`finbot/assistant.py`) that calls the model at most 4 times, runs three read-only tools, and returns a draft, an answer or a failure. Drafts live in a new `drafts` table (DB version 4); Save writes all entries in one transaction. Memory of the last 10 messages lives in the process only.

**Tech stack:** Python 3.12, aiogram 3.31.0, sqlite3, `anthropic==2.3.0` (new runtime dependency, approved 01.11), tests with the real SDK over `httpx2.MockTransport`.

**Spec:** `stages/02_spec/output/spec-ai-input-v2-2026-11-01.md` (approved 12.11). Reviews behind it: `stages/02_spec/references/review-ai-input-2026-11-01/`. Requirement ids below (A1.1 ...) are the spec's.

## Global Constraints

- Code in `app/`. Read `_config/engineering-rules.md` and `_config/telegram-rules.md` first. Test first, then the minimal code.
- Gate before every commit: `cd app && .venv/bin/ruff check . && .venv/bin/ruff format --check . && pyright && .venv/bin/pytest -q` (`pyright` is the global binary, run from `app/`).
- One commit per task, pathspec commit of only the task's files, English message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `.agents/`, `.codex/`, `app/.env`, `app/data/`. No push.
- Never read or print `app/.env`. Never touch the server. **No real model call**: no test, script or manual run may reach api.anthropic.com. Tests use `tests/fake_anthropic.py` (Task 1).
- Money stays int cents; amounts from the model are parsed with `money.parse_amount`. Every writer uses `with conn:`; the two multi-step writers (`save_draft`, the daily cap) start with `BEGIN IMMEDIATE` and contain no `await`.
- Model: `claude-sonnet-5-5`, `max_tokens=4096`, `output_config={"effort": "low"}`, no `thinking`, no `tool_choice`, no `temperature`/`top_p`/`top_k`. Client: `AsyncAnthropic(api_key=<key>, base_url="https://api.anthropic.com", timeout=anthropic.Timeout(45.0, connect=5.0), max_retries=2)`.
- Logs never carry the key, the bot token, message text, captions, photos, model answers or tool output. Errors are logged as class name, status code and request id only.
- Model text and draft text are sent with no `parse_mode` (the bot has no default parse mode).
- Bot copy in English, exactly as given in this plan or the spec. Existing tests change only where they pin copy or signatures this plan changes; the report names them.
- Every callback is answered exactly once; "message is not modified" is ignored; callback data stays within 64 bytes. Buttons already sent keep working.
- With no `ANTHROPIC_API_KEY` (absent or empty) the bot behaves exactly as phase 1.3, except the text of `saved_text` for an entry without a keyword (never produced by typed input).

## Review Focus

1. **Save pressed twice quickly** (double tap, or two taps in flight): exactly one set of entries; the second tap answers `Already saved.` Pinned in Task 2 (`save_draft` twice) and Task 7 (two callbacks with `asyncio.gather`).
2. **An album of 3 photos, or two texts sent fast**: answered one after another in arrival order; memory reads user, assistant, user, assistant. Pinned in Task 7 (`asyncio.gather` of two updates, memory order checked).
3. **The model answers in the wrong case or shape** (`"eur"`, `"Expense"`, `"12,50"`, category `"eating out"`, a category of the other kind, an unknown category): normalised or left without category, never refused for case. Pinned in Task 2.
4. **A message written before midnight and handled after it**: "вчера" and the future-date check use the Telegram message date in Vienna, not the processing date. Pinned in Task 7 (message dated 23:59 of 31.10 handled with `today()` = 01.11: the prompt says 31.10 and a 2026-11-01 draft entry is refused).
5. **Secrets and content in logs**, including `ANTHROPIC_LOG=debug` in the environment: the key and the message words never appear. Pinned in Task 1 (filter) and Task 8 (subprocess with `ANTHROPIC_LOG=debug`).

### Task 2: Drafts table and the Save transaction

**Interfaces consumed:** `ledger.Record`, `parser.Entry`, `money.parse_amount`, `money.MAX_CENTS`, `categories.find_category`.

**Interfaces produced (`finbot/drafts.py`):**
```python
DRAFT_TTL = timedelta(hours=48)
MAX_DRAFT_ENTRIES = 10

@dataclass(frozen=True)
class DraftEntry:
    kind: str            # "expense" | "income"
    amount_cents: int
    currency: str        # "EUR" | "USD" | "UAH"
    category_id: int | None
    category: str | None # name when drafted, for display
    note: str
    on: date

@dataclass(frozen=True)
class Draft:
    id: int
    source: str          # "text" | "photo"
    entries: tuple[DraftEntry, ...]
    status: str          # "open" | "saved" | "cancelled" | "replaced" | "expired"
    created_at: datetime # aware, UTC
    message_id: int | None

class DraftError(ValueError): ...      # str() is the reason sent back to the model
class DraftClosed(Exception):           # .status in "saved","cancelled","replaced","expired","gone"
    def __init__(self, status: str) -> None: ...

def check_draft(conn, raw: Mapping[str, Any], source: str, message_date: date) -> tuple[DraftEntry, ...]
def create_draft(conn, entries: tuple[DraftEntry, ...], source: str, replace_open: bool, now: datetime) -> tuple[Draft, Draft | None]
def set_draft_message(conn, draft_id: int, message_id: int) -> None
def get_draft(conn, draft_id: int) -> Draft | None
def save_draft(conn, draft_id: int, now: datetime) -> list[Record]
def cancel_draft(conn, draft_id: int, now: datetime) -> Draft
```
`ledger.insert_transaction(conn, entry: Entry, category_id: int | None) -> int`: the INSERT of `add_transaction` (rate lookup and EUR conversion included) without any commit; `add_transaction` keeps its behaviour by calling it inside `with conn`.

1. **Migration 3 -> 4** in `db.py`, locked and re-checked like `_add_budgets`:
   `CREATE TABLE drafts (id INTEGER PRIMARY KEY, source TEXT NOT NULL CHECK (source IN ('text','photo')), entries TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open','saved','cancelled','replaced','expired')), created_at TEXT NOT NULL, message_id INTEGER)`, then `user_version = 4`. `entries` is JSON: a list of objects `{kind, amount_cents, currency, category_id, category, note, on}`; `created_at` is ISO 8601 UTC.
2. **`check_draft`** (A4.2), in this order, raising `DraftError` with exactly these reasons:
   - not 1 to 10 entries: `a draft holds 1 to 10 entries`
   - `source == "photo"` and not exactly one entry of kind expense: `a receipt is exactly one expense`
   - `kind` (any case) not expense/income: `entry {n}: kind must be expense or income`
   - `currency` (any case) not EUR/USD/UAH: `entry {n}: currency must be EUR, USD or UAH`
   - `parse_amount(amount)` fails: `entry {n}: amount must be like 25 or 12.50, above zero, at most 10000000`
   - `date` not `YYYY-MM-DD` (exactly 10 characters, `date.fromisoformat`): `entry {n}: date must be YYYY-MM-DD`
   - date after `message_date`: `entry {n}: {date} is after the message date`
   - A missing or non-string field fails the check for that field.
   - Category: `find_category(conn, name)` of the same kind -> its id and stored name; empty, unknown or the other kind -> `None`.
   - Note: `" ".join(note.split())`, then leading `=`, `+`, `-`, `@` and spaces stripped, then cut to 99 characters plus `…` when longer than 100; empty -> the category name, or `receipt` when there is no category.
3. **`create_draft`**: in one `with conn`: when `replace_open` is true and `source == "text"`, the newest open draft with source `text` becomes `replaced` and is returned as the second value (else `None`); the new draft is inserted with status `open` and `created_at = now`.
4. **`save_draft`** (A6.1, A6.3, A6.4): `with conn:` + `BEGIN IMMEDIATE`; no row -> `DraftClosed("gone")`; status not open -> `DraftClosed(status)`; `now - created_at > DRAFT_TTL` -> set status `expired`, commit, then raise `DraftClosed("expired")` (raise after the `with` block, or the update rolls back); otherwise set status `saved`, insert every entry with `insert_transaction(conn, Entry(kind, cents, currency, note, "", None, on), category_id)`, commit once, return the saved records in draft order. Any `sqlite3.Error` rolls everything back and propagates.
5. **`cancel_draft`**: same checks and expiry as Save; sets `cancelled`, returns the updated draft.
- [ ] Tests (`test_db.py`, `test_drafts.py`, `test_ledger.py`):
  - migration on a version-3 database with data keeps every entry and budget; the locked re-check (a second `connect` finds 4 and skips); phase 1.3 ledger functions (`add_transaction`, `records_between`) work on version 4.
  - `check_draft`: every reason above with its exact text; `"eur"`, `"Expense"`, `"12,50"` -> EUR, expense, 1250; category `"eating out"` -> Eating out; category `"Salary"` on an expense -> `None`; unknown -> `None`; note `"=SUM(A1)\n  coffee"` -> `SUM(A1) coffee`; 120-character note -> 100 characters ending `…`; empty note with no category -> `receipt`; photo with two entries or with one income refused; entry dated `message_date` accepted, the next day refused; 11 entries refused.
  - `create_draft` with `replace_open=True` replaces only the newest open text draft (an older open one and a photo draft stay open); with `False` nothing is replaced.
  - `save_draft`: 3 entries saved with their category ids, empty keyword, notes and dates; USD with a rate gets EUR, USD without a rate stays pending; second call raises `DraftClosed("saved")` and adds nothing; cancelled -> `DraftClosed("cancelled")`; 48 h + 1 s old -> `DraftClosed("expired")` and status is `expired` in the table; 47 h 59 min saves; unknown id -> `"gone"`; a forced `sqlite3.IntegrityError` on the second insert (monkeypatch `insert_transaction`) leaves the draft `open` and no entry.
